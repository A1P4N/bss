# Правила Coding Agent для BSS

## 1. Источник истины

Приоритет:

1.  утверждённые требования проекта;
2.  Event Model;
3.  это ЧТЗ;
4.  архитектурные решения;
5.  технические решения агента.

Если два нормативных документа противоречат друг другу --- не угадывать.

------------------------------------------------------------------------

## 2. Не смешивать уровни

``` text
Infrastructure
      ↓
Domain
      ↓
Application
      ↓
Interface
```

Конкретный HTTP/API/storage код не должен проникать в domain.

------------------------------------------------------------------------

## 3. Dependency direction

Предпочтительно:

``` text
CLI
 ↓
Application
 ↓
Domain interfaces
 ↑
Infrastructure implementations
```

------------------------------------------------------------------------

## 4. Idempotency

Операции загрузки и recovery должны быть безопасны при повторном
запуске.

------------------------------------------------------------------------

## 5. Atomicity

Dataset не должен становиться `READY` до завершения validation.

------------------------------------------------------------------------

## 6. Immutability

Published Dataset version после `READY` считается неизменяемой.

Для исправления создаётся новая версия либо используется явно
определённый recovery mechanism с изменением версии.

------------------------------------------------------------------------

## 7. Errors

Ошибки должны быть:

-   типизированными;
-   логируемыми;
-   диагностируемыми;
-   не скрываться `except Exception: pass`.

------------------------------------------------------------------------

## 8. Logging

Не логировать credentials.

Структурированные логи должны содержать context:

``` text
job_id
dataset_id
symbol
timeframe
operation
```

------------------------------------------------------------------------

## 9. Testing

Каждый новый service должен иметь unit tests.

Каждая интеграционная граница должна иметь integration test.

Каждый bug, обнаруженный после реализации, должен получать regression
test.

------------------------------------------------------------------------

## 10. Determinism

Не использовать:

-   случайный порядок коллекций;
-   недетерминированные parallel merge;
-   локальное время;
-   implicit timezone;
-   hidden state.

Если нужен random --- seed должен быть частью configuration.

------------------------------------------------------------------------

## 11. Time

Всегда использовать timezone-aware UTC timestamps.

Не использовать naive datetime.

------------------------------------------------------------------------

## 12. Data validation

Не считать Dataset валидным только потому, что source API вернул HTTP
200.

Проверять содержимое.

------------------------------------------------------------------------

## 13. Replay

Replay должен иметь явный `run_id`.

Все replay inputs должны быть фиксированы.

------------------------------------------------------------------------

## 14. Look-ahead

Нельзя:

-   читать весь future Dataset в анализатор;
-   сортировать данные так, чтобы future candle стала доступна раньше
    времени;
-   использовать future metadata, если она влияет на decision;
-   использовать final Dataset state вместо state as-of replay time.

------------------------------------------------------------------------

## 15. Intrabar

Если невозможно доказать порядок событий:

``` text
unknown
```

а не:

``` text
assume favorable order
```

------------------------------------------------------------------------

## 16. Performance

Сначала корректность и детерминизм.

Потом оптимизация.

Не добавлять premature caching, multiprocessing или distributed
execution.

------------------------------------------------------------------------

## 17. Documentation

Любой публичный интерфейс должен иметь документацию.

Любое нетривиальное архитектурное решение должно быть отражено в ADR.

------------------------------------------------------------------------

## 18. Backward compatibility

Если существующий репозиторий уже содержит public API или data format,
не ломать его без явной необходимости.

------------------------------------------------------------------------

## 19. Scope discipline

Не расширять задачу самостоятельно.

Если видишь потенциальное улучшение:

``` text
TODO / follow-up
```

а не дополнительную реализацию.

------------------------------------------------------------------------

## 20. Final checklist

Перед завершением:

``` text
[ ] tests pass
[ ] no credentials in repository
[ ] no BSS strategy logic in Loader
[ ] no look-ahead
[ ] deterministic replay
[ ] UTC everywhere
[ ] dataset metadata complete
[ ] recovery tested
[ ] checkpoint tested
[ ] event envelope validated
[ ] documentation updated
[ ] TBD preserved
```
